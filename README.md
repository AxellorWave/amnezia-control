## ⚡ Быстрый старт

Одна команда на сервере (Debian / Ubuntu, под root):

```bash
curl -fsSL https://raw.githubusercontent.com/AxellorWave/amnezia-control/master/deploy.sh -o deploy.sh && sudo bash deploy.sh
```

Скрипт:

1. ставит Docker и Docker Compose, если их нет (не трогает уже установленный Docker с Amnezia);
2. клонирует проект в `/opt/amnezia-bot`;
3. по шагам спрашивает нужные данные — `BOT_TOKEN`, `ADMIN_IDS`, `VPN_HOST` и остальное — и записывает `.env`;
4. запускает бота через `docker compose`.

Дальше откройте бота в Telegram, отправьте `/start` и установите протоколы в разделе **Админка → 🧩 Протоколы**.

> Подготовьте заранее: токен бота от [@BotFather](https://t.me/BotFather), свой Telegram ID и (желательно) домен с A-записью на IP сервера.

## 📋 Требования

- VPS на Linux (Debian / Ubuntu) с root-доступом.
- Docker и Docker Compose (быстрый старт поставит сам).
- Домен или поддомен — очень желательно (для подписок, сертификата и смены IP).
- Telegram-бот и токен от [@BotFather](https://t.me/BotFather).

> Приложение AmneziaVPN для установки сервера **больше не обязательно**: все протоколы ставятся из бота. Если сервер уже настроен через приложение, бот найдёт контейнеры Amnezia и будет работать с ними.

## 🌐 Домен

Если в конфигах и подписках указан домен, при смене IP сервера пользователям не нужно ничего менять — достаточно поменять одну DNS-запись.

| Тип | Хост  | Значение   | TTL                  |
|-----|-------|------------|----------------------|
| A   | `vpn` | IP сервера | минимальный (60–300) |

Проверка (должен вывести IP сервера):

```bash
dig +short vpn.example.com @8.8.8.8
```

Если домена нет, укажите в `VPN_HOST` IP сервера — всё будет работать, но после смены IP конфиги придётся выдавать заново, а для Hysteria2 будет только самоподписанный сертификат.

## 🤖 Создание Telegram-бота

1. Откройте [@BotFather](https://t.me/BotFather) → `/newbot` → задайте имя и username. Сохраните **токен**.
2. Узнайте свой Telegram ID, например, у [@userinfobot](https://t.me/userinfobot). Это будет ID администратора.

## 🛠 Ручная установка

<details>
<summary><b>1. Docker и Docker Compose</b></summary>

```bash
docker --version && docker compose version
```

Если Docker нет — официальная инструкция: https://docs.docker.com/engine/install/. Если нет Compose:

```bash
apt update && apt install -y docker-compose-v2      # Ubuntu
```

> Если на сервере уже стоит Amnezia — не переустанавливайте Docker поверх, это может остановить VPN.

Также понадобятся `git` и `dnsutils`: `apt install -y git dnsutils`.

</details>

<details>
<summary><b>2. Загрузка проекта на сервер</b></summary>

```bash
git clone https://github.com/AxellorWave/amnezia-control.git /opt/amnezia-bot
cd /opt/amnezia-bot
```

Для приватного репозитория используйте deploy key:

```bash
ssh-keygen -t ed25519 -f ~/.ssh/amnezia_bot -N "" -C "amnezia-bot deploy"
cat ~/.ssh/amnezia_bot.pub      # → GitHub: Settings → Deploy keys → Add deploy key
cat >> ~/.ssh/config <<'EOF'
Host github-amnezia-bot
    HostName github.com
    User git
    IdentityFile ~/.ssh/amnezia_bot
    IdentitiesOnly yes
EOF
git clone git@github-amnezia-bot:AxellorWave/amnezia-control.git /opt/amnezia-bot
```

</details>

<details>
<summary><b>3. Настройка и запуск</b></summary>

```bash
cp .env.example .env
nano .env                         # см. раздел «Настройка .env»
docker compose up -d --build
docker compose logs -f
```

Бот работает в сети хоста (`network_mode: host`): так он видит API Xray и Hysteria на `127.0.0.1`, а Hysteria — auth-хук бота. Откройте бота в Telegram и отправьте `/start`.

На пустом сервере бот запустится и напишет администратору «VPN ещё не настроен», а пользователи увидят «VPN пока не настроен, администратор уже в курсе».

```bash
docker compose ps           # статус
docker compose restart      # перезапуск
docker compose logs --tail 100
```

</details>

## ⚙️ Настройка .env

| Переменная | Обязательна | Описание |
|---|:-:|---|
| `BOT_TOKEN` | ✅ | Токен от @BotFather |
| `ADMIN_IDS` | ✅ | Telegram ID администраторов через запятую |
| `VPN_HOST` | ✅ | Домен (`vpn.example.com`) или IP сервера |
| `SERVER_NAME` | | Имя сервера в приложениях и название подписки (`vpn`) |
| `DNS1`, `DNS2` | | DNS в конфигах AmneziaWG (`1.1.1.1`, `1.0.0.1`) |
| `MTU` | | MTU для ключа `vpn://` (`1280`) |
| `KEEPALIVE` | | PersistentKeepalive; пусто — как в приложении (`25-35` для AWG 2) |
| `MAX_DEVICES` | | Лимит устройств на человека: AWG-устройства + устройства подписки (`5`, у админов без лимита) |
| `CUSTOM_EMOJI` | | Кастомные эмодзи (`1`); `0` — обычные |
| `SUB_HOST` | | Адрес в ссылке подписки (по умолчанию `VPN_HOST`) |
| `SUB_PORT` | | Порт сервера подписок (`2096`, TCP) |
| `SUB_LISTEN` | | Адрес прослушивания сервера подписок (`0.0.0.0`) |
| `HWID_REQUIRED` | | `1` — не отдавать подписку клиентам без заголовка `x-hwid`; `0` — считать их «неизвестным устройством» (`0`) |
| `BACKUP_EVERY_DAYS` | | Полная копия админам раз в N дней (`0` — выключено) |
| `BACKUP_KEEP` | | Сколько последних копий хранить в `data/backups/` (`7`) |
| `HOST_DATA_DIR` | | Путь к `./data` на хосте. Определяется сам через `docker inspect`; задайте, если бот пишет, что не может его найти |
| `HY2_AUTH_PORT`, `XRAY_API_PORT`, `HY2_STATS_PORT` | | Служебные порты на `127.0.0.1` (`18081`, `10085`, `18082`) |
| `CONTAINER`, `CONF_DIR`, `IFACE`, `WG_BIN`, `WG_QUICK_BIN` | | **Необязательные.** AmneziaWG определяется автоматически: `amnezia-awg2` (AWG 2.0, `awg0.conf`) или старый `amnezia-awg` (`wg0.conf`), утилиты `awg`/`wg` — по наличию в контейнере. Значения из прошлых версий `.env` продолжают работать |

> 💎 Кастомные эмодзи работают, только если у владельца бота есть **Telegram Premium**. Без него бот сам переключится на обычные.

## 🧩 Протоколы

Раздел **Админка → 🧩 Протоколы** показывает, что найдено на сервере: откуда протокол («из приложения Amnezia» или «установлен ботом»), состояние (работает / остановлен / нет), порты и число клиентов. Остальные контейнеры `amnezia-*` (OpenVPN, WireGuard, IPsec, DNS…) показываются как «установлено, ботом не поддерживается» — чтобы было видно, что занимает порты.

Установка — кнопка «Установить …»: мастер с параметрами, проверка занятости портов (с указанием, кто занимает) и прогресс в одном сообщении.

| Протокол | Как ставится |
|---|---|
| 🛡 **AmneziaWG 2.0** | Как в приложении AmneziaVPN: сеть `amnezia-dns-net`, образ `amnezia-awg2` из `amneziavpn/amneziawg-go`, `configure_container.sh`, файрвол хоста, `start.sh`. Скрипты лежат в `app/protocols/amnezia_scripts/awg/` с указанием коммита-источника. Сервер потом можно добавить в приложение AmneziaVPN по SSH — оно увидит клиентов бота |
| ⚡ **VLESS (Xray)** | Официальный `ghcr.io/xtls/xray-core` (версия зафиксирована, обновление — кнопкой с changelog). VLESS + REALITY + Vision; запасной VLESS + XHTTP + REALITY. Цель REALITY проверяется на TLS 1.3 и h2 и меняется кнопкой «Сменить цель REALITY» в карточке протокола (после смены клиентам нужно обновить подписку). Заблокирован BitTorrent. Контейнер запускается от root, иначе Xray не может слушать порт 443 |
| 🐇 **Hysteria 2** | Официальный `tobyxdd/hysteria` (версия зафиксирована). Пароли проверяет бот (HTTP auth-хук), Salamander, BBR. Сертификат — Let's Encrypt по домену (нужен свободный `80/tcp` на время выпуска, продление — автоматически) или самоподписанный с `pinSHA256` в ссылке |
| 🇷🇺 **Блок RU** (VLESS, Hysteria 2) | По умолчанию **выключен**. Если включить (при установке или кнопкой в карточке протокола), сервер не пускает через VPN на российские домены и IP: сервер не светится в российских сервисах, но у клиентов без маршрутизации «RU — напрямую» российские сайты перестают открываться. Пока блок включён, пользователи видят в «Моей подписке» и в инструкциях красное предупреждение со ссылкой на «Списки сервисов», а сервер в приложении подписан «без RU»; когда выключен — мягкий совет настроить раздельное туннелирование |

### 🔌 Порты

| Что | Порт по умолчанию | Где слушает |
|---|---|---|
| AmneziaWG 2.0 | `55424/udp` | наружу |
| VLESS + REALITY + Vision | `443/tcp` | наружу |
| VLESS + XHTTP (запасной) | `8443/tcp` | наружу |
| Hysteria 2 | `443/udp` | наружу |
| Сервер подписок | `2096/tcp` (`SUB_PORT`) | наружу |
| Let's Encrypt (на время выпуска) | `80/tcp` | наружу |
| API Xray | `10085` | `127.0.0.1` |
| auth-хук Hysteria 2 | `18081` | `127.0.0.1` |
| Статистика Hysteria 2 | `18082` | `127.0.0.1` |

Свои контейнеры бот запускает с `--network host --restart unless-stopped --label vpnbot.proto=<id>`, их конфиги лежат в `data/xray/`, `data/hy2/`, сертификаты — в `data/certs/`.

Если включён `ufw` или `firewalld`, после установки бот предложит открыть порты отдельной кнопкой (молча ничего не открывает). Файрвол в панели хостинга (security groups) нужно открыть самостоятельно.

<details>
<summary><b>⚡ XRay от Amnezia</b></summary>

`amnezia-xray` ботом не управляется — он показывается в «Протоколах». Кнопка «Заменить на оригинальный Xray» проходит все подтверждения удаления (с архивом `/opt/amnezia/xray/`), удаляет его и открывает мастер установки. Клиенты XRay из приложения после замены перестанут работать.

</details>

<details>
<summary><b>🗑 Удаление протокола</b></summary>

Кнопка «🗑 Удалить» в карточке протокола:

1. Экран «что будет потеряно»: контейнер, происхождение, сколько людей, устройств и клиентов из приложения затронуто.
2. Бот делает резервную копию, присылает её файлом и спрашивает «Точно удалить?». Для AWG и XRay от Amnezia можно отдельно отметить «удалить образ и данные».
3. Нужно прислать название протокола (`AWG`, `VLESS`, `HY2`) или 4-значный код с экрана, за 2 минуты. Любой другой ответ — отмена.

После удаления AWG-устройства удаляются из бота (трафик остаётся за людьми), у Xray/Hysteria2 креды пользователей сохраняются. Затронутые пользователи получают сообщение. Сеть `amnezia-dns-net` удаляется, только если к ней больше никто не подключён. Кнопки старых экранов после отмены или выполнения не срабатывают.

Перед каждой записью конфига сервера бот сохраняет копию в `data/backups/<протокол>/<время>/`.

</details>

## 🔗 Подписки и устройства (HWID)

У каждого пользователя одна ссылка подписки `https://SUB_HOST:SUB_PORT/sub/<токен>` со всеми установленными и работающими протоколами (VLESS, VLESS XHTTP, Hysteria2). Ссылки внутри — через домен `VPN_HOST`, не IP. Приложения обновляют подписку сами (раз в час).

- 🔒 Если для `SUB_HOST` есть сертификат Let's Encrypt, подписки отдаются по HTTPS. Кнопка «Сертификат для подписок» в «Протоколах» выпускает его (нужен свободный `80/tcp`).
- 🚫 Неизвестный или отозванный токен → `404`. Есть ограничение частоты запросов с одного IP.
- ↩️ Отзыв доступа убирает пользователя из Xray и рвёт сессии Hysteria2; повторное одобрение возвращает.
- 🔁 «Перевыпустить ссылку» — новые токен, UUID и пароль Hysteria2; старые подключения рвутся, список устройств подписки очищается.
- 📲 Кнопки «Открыть в Happ / Incy / v2RayTun / Hiddify» ведут на страницу `/open/<приложение>/<токен>`, которая добавляет подписку в приложение (Telegram не пускает такие ссылки в кнопки напрямую).

**HWID и лимит.** Клиенты вроде Happ при обновлении подписки присылают идентификатор устройства (`x-hwid`, `x-device-os`, `x-ver-os`, `x-device-model`). Бот записывает устройство и показывает его в «Устройствах подписки». Новое устройство сверх лимита получает вместо серверов заглушку «Лимит устройств — удали лишнее в боте», а **сам пользователь** (не админ) получает сообщение с кнопкой «Мои устройства подписки» — не чаще раза в час на одно устройство. Клиенты без HWID учитываются как «неизвестное устройство» по User-Agent (или получают отказ при `HWID_REQUIRED=1`). Лимит — общий для AWG-устройств и устройств подписки.

> ⚠️ Честно: HWID ограничивает **получение подписки**, а не сами подключения. Ссылки, скопированные из подписки вручную, работают до перевыпуска ссылки. У всех устройств человека одни креды VLESS/Hysteria2 — протоколы это допускают; трафик подписки виден суммарно по человеку.

## 🔀 Раздельное туннелирование и списки сервисов

**Раздельное туннелирование** — через VPN идут только нужные сайты и приложения (или наоборот, всё, кроме выбранных). Так быстрее, а российские сайты и приложения не видят VPN. Инструкции для каждого клиента — в боте: **ℹ️ Как подключиться → Раздельное туннелирование** и **Моя подписка → Раздельное туннелирование**.

| Клиент | Что умеет |
|---|---|
| **Happ** | Профили маршрутизации (прокси / напрямую по сайтам и IP), добавляются ссылкой `happ://routing/…` или приезжают вместе с подпиской; на Android — выбор приложений |
| **Incy** | Профили маршрутизации в том же формате (`incy://routing/…`), выбор приложений |
| **v2RayTun** | Правила маршрутизации Xray (домены и IP) |
| **Hiddify** | Маршрутизация по региону и правила sing-box; на Android — прокси для выбранных приложений |
| **AmneziaVPN** | «Раздельное туннелирование» сайтов с импортом/экспортом списка (`.json`) и приложений (Android, Windows) |
| **DefaultVPN** | Как AmneziaVPN, если в версии приложения есть эта настройка |
| **AmneziaWG / `.conf`** | Через `AllowedIPs` — только перечисленные подсети идут через VPN |

**Режимы:**

- **Через VPN — только выбранные** — например, YouTube, Instagram и нейросети идут через VPN, остальное напрямую.
- **Всё через VPN, кроме выбранных** — например, российские сервисы и банки открываются напрямую, остальное через VPN.

| Приложение | Что присылает бот |
|---|---|
| Happ / Incy | Профиль маршрутизации + кнопка «Добавить в …» (страница `/routing/<приложение>/<токен>` открывает `happ://routing/onadd/…` / `incy://routing/onadd/…`) |
| Hiddify | Rule-set sing-box (`.json`) + списки доменов и подсетей |
| v2RayTun | Правила маршрутизации Xray (`.json`) |
| AmneziaVPN / DefaultVPN | Список сайтов для импорта в «Раздельное туннелирование» (`.json`) |
| AmneziaWG (`.conf`) | Конфиг устройства с готовыми `AllowedIPs` (для каждого AWG-устройства человека); большие списки бот укрупняет в подсети и предупреждает |
| Другие | `domains.txt` и `ips.txt` |

✨ **Автоматически для Happ и Incy:** выбранные списки приезжают вместе с подпиской (заголовок `routing`) — при обновлении подписки приложение само получает профиль маршрутизации. Слишком большие профили так не отправляются — тогда используйте файл или кнопку «Добавить в …».

Списки берутся из открытых поддерживаемых источников (itdoginfo/allow-domains, iplist.opencck.org и его бета-версия — их же рекомендует AmneziaVPN, официальные подсети Telegram), обновляются раз в сутки и кешируются в `data/routes/`; новые сервисы подгружаются в течение часа после запуска. Если источник недоступен — используется встроенный каталог доменов. Общие домены CDN и облаков (`google.com`, `amazonaws.com`, Akamai, Cloudflare, Fastly и т.п.) из источников отбрасываются, чтобы через VPN не шла половина интернета.

**Свои сервисы** — админка → **Сервисы обхода**: добавить сервис со своими доменами и IP/подсетями в любую тему, дописать или убрать адреса у встроенного сервиса (убранные адреса из источников не вернутся при обновлении), сбросить правки, скрыть ненужный сервис и вернуть его из «Скрытых». Правки хранятся в базе бота (таблица `route_overrides`) и попадают в резервные копии.

## 💾 Резервные копии и переезд

Формат — `.tar.gz` с `manifest.json` (тип, версия формата, происхождение, дата, порты, sha256 файлов):

| Тип | Что внутри |
|---|---|
| **awg** | `awg0.conf`/`wg0.conf`, ключи сервера, PSK, `clientsTable`, `start.sh`, параметры контейнера |
| **xray** | `config.json` и настройки (ключи REALITY, порты, SNI) |
| **hy2** | Конфиг, сертификат и ключ (или признак самоподписанного), пароль Salamander |
| **full** | Все установленные протоколы + снимок `bot.db` + `.env` без `BOT_TOKEN` (токен — по отдельному выбору) |

> 🔐 В копиях приватные ключи — **не пересылайте их никому**.

**Создание:** «💾 Резервная копия» в карточке протокола, «Полная копия» в «Протоколах»; автоматически — перед удалением, заменой и восстановлением; по расписанию — `BACKUP_EVERY_DAYS`.

**Восстановление:** «♻️ Восстановить из копии» → прислать файл боту (до 20 МБ). Бот проверяет архив (манифест, хеши, версию, защита от выхода за пределы каталога), показывает, что будет восстановлено, и после подтверждения восстанавливает. AmneziaWG восстанавливается **с теми же ключами** — старые конфиги клиентов продолжают работать. Если протокол уже установлен, сначала удалите его (это сделает автокопию). После восстановления бот сверяет клиентов в конфигах с базой и предлагает добавить недостающих или удалить лишних.

> 🚚 **Переезд на новый сервер:** новый VPS → [быстрый старт](#-быстрый-старт) → «Восстановить из копии» (полная) → сменить A-запись домена → «📣 Обновите подписку». Конфиги AWG и подписки у пользователей остаются прежними.

## 🚨 Смена IP и мониторинг блокировок

Если в `VPN_HOST` домен: смените IP у хостера, обновите A-запись — пользователи просто переподключаются.

Бот раз в несколько минут проверяет доступность сервера **из России** и из-за рубежа (check-host.net): TCP-порты Xray и сервера подписок (подписка — только если установлен Xray или Hysteria 2). AmneziaWG по UDP снаружи не проверить, поэтому он считается рабочим, если клиенты делали рукопожатие за последние 5 минут, иначе — «нет данных». Итог: всё хорошо / IP заблокирован / сервер недоступен / частично / не удалось проверить.

**Блокировка IP** (отдельная кнопка в админке): раз в час IP сервера и домен `VPN_HOST` проверяются по реестрам блокировок через [cheburcheck.ru](https://cheburcheck.ru). Если состояние меняется (попал в списки или убрали), бот пишет админам.

<details>
<summary><b>Режим инцидента</b></summary>

Открывается одинаково — по фоновой проверке или когда пользователь нажал «🆘 Не работает VPN»:

- администратору — уведомление с деталями по узлам и подсказкой «смени IP и обнови A-запись»;
- активным пользователям (в сети или действовали в боте за 10 минут) — сообщение, что администратор уже чинит; остальным — баннер при заходе в бота;
- пока инцидент открыт, бот следит за внешним IP сервера, A-записью `VPN_HOST` на резолверах 8.8.8.8, 1.1.1.1 и 77.88.8.8 (Яндекс) с учётом TTL, и проверяет новый IP из России;
- когда всё прошло — инцидент закрывается: админу — время простоя, всем, кто получил сообщение или баннер, — «VPN снова работает». Кнопка «✅ Починил» у админа только запускает внеочередную проверку.

</details>

## 🔄 Обновление

```bash
cd /opt/amnezia-bot
git pull
docker compose up -d --build
```

База и конфиги протоколов хранятся в `./data` и при обновлении не теряются. При обновлении со старой версии база мигрирует автоматически, существующие пользователи и устройства работают как раньше.

Юнит-тесты (без Docker): `pip install -r requirements.txt pytest && pytest -q`.

## ❓ Решение проблем

<details>
<summary><b>Бот пишет «Нет доступа к Docker»</b></summary>

Проверьте, что `/var/run/docker.sock` смонтирован (см. `docker-compose.yml`).

</details>

<details>
<summary><b>Установка своих контейнеров падает с ошибкой пути</b></summary>

Бот не смог определить путь к `./data` на хосте; укажите `HOST_DATA_DIR=/opt/amnezia-bot/data` в `.env`.

</details>

<details>
<summary><b>Порт занят</b></summary>

Мастер установки покажет, кто его занимает; выберите другой порт или освободите.

</details>

<details>
<summary><b>Конфиг или подписка выдаётся, но не подключается</b></summary>

- `dig +short vpn.example.com @8.8.8.8` должен вернуть IP сервера;
- порты протоколов открыты в файрволе хостинга и в `ufw`/`firewalld`;
- AWG: `docker exec amnezia-awg2 awg show` — появляется ли handshake;
- Xray: `docker logs vpnbot-xray`; Hysteria: `docker logs vpnbot-hysteria`.

</details>

<details>
<summary><b>Сообщения без форматирования</b></summary>

Бот использует rich-сообщения; если они недоступны, присылает обычные. Обновите Telegram.

</details>

<details>
<summary><b>Вместо красивых иконок — обычные эмодзи</b></summary>

Кастомные эмодзи требуют Telegram Premium у владельца бота. Без него бот показывает обычные эмодзи — это нормально. Отключить явно: `CUSTOM_EMOJI=0` в `.env`.

</details>

> 🔐 **Безопасность.** Бот получает доступ к Docker через `/var/run/docker.sock`, то есть фактически root-доступ к серверу. Не передавайте никому `.env`, токен бота и резервные копии.
