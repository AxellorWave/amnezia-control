# amnezia-bot

Telegram-бот, который сам ставит VPN на сервер и раздаёт доступ: **AmneziaWG 2.0**, **VLESS** (оригинальный XTLS Xray-core) и **Hysteria 2**.

- Доступ по заявке: новый пользователь отправляет заявку, администратор одобряет её кнопкой.
- **Автоопределение**: при запуске, раз в 5 минут и по кнопке бот находит, что уже стоит на сервере (контейнеры Amnezia и свои), и показывает только установленное. Бот запускается и на пустом сервере.
- **Установка из бота** (раздел «🧩 Протоколы»): AmneziaWG 2.0 — так же, как ставит приложение AmneziaVPN; VLESS + REALITY (Vision и запасной XHTTP); Hysteria 2 с обфускацией Salamander.
- **Удаление** протоколов с тремя подтверждениями и автоматической резервной копией.
- **Резервные копии и восстановление** протоколов и всего бота, в том числе переезд на новый сервер.
- **AmneziaWG** — по устройствам: у каждого устройства свой конфиг (ключ `vpn://`, QR, файл `.conf`).
- **Подписка** (VLESS + Hysteria2) — одна ссылка на все устройства человека, как у платных VPN. Устройства учитываются по HWID, о превышении лимита бот пишет самому пользователю.
- Инструкции для приложений, раздельное туннелирование и готовые списки сервисов для импорта в клиенты.
- Рассылки (любые сообщения, альбомы, премиум-эмодзи), личные сообщения и ответы пользователей.
- Мониторинг доступности сервера из России, режим инцидента при блокировке IP и кнопка «🆘 Не работает VPN».
- Накопительный учёт трафика по всем протоколам, статус и дашборд.
- Оформление на rich-сообщениях Telegram и кастомных эмодзи.
- В конфигах и подписках вместо IP используется домен — после смены IP достаточно обновить DNS-запись.

Бот управляет сервером только через `docker.sock` — никаких панелей. Клиенты AmneziaWG, созданные ботом, видны в приложении AmneziaVPN, а клиенты из приложения — в админке бота.

## 1. Требования

- VPS на Linux (Debian / Ubuntu) с root-доступом.
- Docker и Docker Compose.
- Домен или поддомен — очень желательно (для подписок, сертификата и смены IP).
- Telegram-бот и токен от [@BotFather](https://t.me/BotFather).

Приложение AmneziaVPN для установки сервера **больше не обязательно**: все протоколы ставятся из бота. Если сервер уже настроен через приложение, бот найдёт контейнеры Amnezia и будет работать с ними.

## 2. Домен

Если в конфигах и подписках указан домен, при смене IP сервера пользователям не нужно ничего менять — достаточно поменять одну DNS-запись.

| Тип | Хост  | Значение   | TTL                  |
|-----|-------|------------|----------------------|
| A   | `vpn` | IP сервера | минимальный (60–300) |

Проверка (должен вывести IP сервера):

```bash
dig +short vpn.example.com @8.8.8.8
```

Если домена нет, укажите в `VPN_HOST` IP сервера — всё будет работать, но после смены IP конфиги придётся выдавать заново, а для Hysteria2 будет только самоподписанный сертификат.

## 3. Создание Telegram-бота

1. Откройте [@BotFather](https://t.me/BotFather) → `/newbot` → задайте имя и username. Сохраните **токен**.
2. Узнайте свой Telegram ID, например, у [@userinfobot](https://t.me/userinfobot). Это будет ID администратора.

## 4. Docker и Docker Compose

```bash
docker --version && docker compose version
```

Если Docker нет — официальная инструкция: https://docs.docker.com/engine/install/. Если нет Compose:

```bash
apt update && apt install -y docker-compose-v2      # Ubuntu
```

> Если на сервере уже стоит Amnezia — не переустанавливайте Docker поверх, это может остановить VPN.

Также понадобятся `git` и `dnsutils`: `apt install -y git dnsutils`.

## 5. Загрузка проекта на сервер

```bash
git clone https://github.com/AxellorWave/amnezia-control.git /opt/amnezia-bot
cd /opt/amnezia-bot
```

Для приватного репозитория используйте deploy key:

```bash
ssh-keygen -t ed25519 -f ~/.ssh/amnezia_bot -N "" -C "amnezia-bot deploy"
cat ~/.ssh/amnezia_bot.pub      # → GitHub: Settings → Deploy keys → Add deploy key
cat >> ~/.ssh/config <<'EOF'
Host github-amnezia-bot
    HostName github.com
    User git
    IdentityFile ~/.ssh/amnezia_bot
    IdentitiesOnly yes
EOF
git clone git@github-amnezia-bot:AxellorWave/amnezia-control.git /opt/amnezia-bot
```

## 6. Настройка .env

```bash
cp .env.example .env
nano .env
```

| Переменная | Обязательна | Описание |
|---|:-:|---|
| `BOT_TOKEN` | да | Токен от @BotFather |
| `ADMIN_IDS` | да | Telegram ID администраторов через запятую |
| `VPN_HOST` | да | Домен (`vpn.example.com`) или IP сервера |
| `SERVER_NAME` | | Имя сервера в приложениях и название подписки (`vpn`) |
| `DNS1`, `DNS2` | | DNS в конфигах AmneziaWG (`1.1.1.1`, `1.0.0.1`) |
| `MTU` | | MTU для ключа `vpn://` (`1280`) |
| `KEEPALIVE` | | PersistentKeepalive; пусто — как в приложении (`25-35` для AWG 2) |
| `MAX_DEVICES` | | Лимит устройств на человека: AWG-устройства + устройства подписки (`5`, у админов без лимита) |
| `CUSTOM_EMOJI` | | Кастомные эмодзи (`1`); `0` — обычные |
| `SUB_HOST` | | Адрес в ссылке подписки (по умолчанию `VPN_HOST`) |
| `SUB_PORT` | | Порт сервера подписок (`2096`, TCP) |
| `SUB_LISTEN` | | Адрес прослушивания сервера подписок (`0.0.0.0`) |
| `HWID_REQUIRED` | | `1` — не отдавать подписку клиентам без заголовка `x-hwid`; `0` — считать их «неизвестным устройством» (`0`) |
| `BACKUP_EVERY_DAYS` | | Полная копия админам раз в N дней (`0` — выключено) |
| `BACKUP_KEEP` | | Сколько последних копий хранить в `data/backups/` (`7`) |
| `HOST_DATA_DIR` | | Путь к `./data` на хосте. Определяется сам через `docker inspect`; задайте, если бот пишет, что не может его найти |
| `HY2_AUTH_PORT`, `XRAY_API_PORT`, `HY2_STATS_PORT` | | Служебные порты на `127.0.0.1` (`18081`, `10085`, `18082`) |
| `CONTAINER`, `CONF_DIR`, `IFACE`, `WG_BIN`, `WG_QUICK_BIN` | | **Необязательные.** AmneziaWG определяется автоматически: `amnezia-awg2` (AWG 2.0, `awg0.conf`) или старый `amnezia-awg` (`wg0.conf`), утилиты `awg`/`wg` — по наличию в контейнере. Значения из прошлых версий `.env` продолжают работать |

> Кастомные эмодзи работают, только если у владельца бота есть **Telegram Premium**. Без него бот сам переключится на обычные.

## 7. Запуск

```bash
cd /opt/amnezia-bot
docker compose up -d --build
docker compose logs -f
```

Бот работает в сети хоста (`network_mode: host`): так он видит API Xray и Hysteria на `127.0.0.1`, а Hysteria — auth-хук бота. Откройте бота в Telegram и отправьте `/start`.

На пустом сервере бот запустится и напишет администратору «VPN ещё не настроен», а пользователи увидят «VPN пока не настроен, администратор уже в курсе».

```bash
docker compose ps           # статус
docker compose restart      # перезапуск
docker compose logs --tail 100
```

## 8. Протоколы: установка, удаление, порты

Раздел **Админка → 🧩 Протоколы** показывает, что найдено на сервере: откуда протокол («из приложения Amnezia» или «установлен ботом»), состояние (работает / остановлен / нет), порты и число клиентов. Остальные контейнеры `amnezia-*` (OpenVPN, WireGuard, IPsec, DNS…) показываются как «установлено, ботом не поддерживается» — чтобы было видно, что занимает порты.

Установка — кнопка «Установить …»: мастер с параметрами, проверка занятости портов (с указанием, кто занимает) и прогресс в одном сообщении.

| Протокол | Как ставится | Порты по умолчанию |
|---|---|---|
| AmneziaWG 2.0 | Как в приложении AmneziaVPN: сеть `amnezia-dns-net`, образ `amnezia-awg2` из `amneziavpn/amneziawg-go`, `configure_container.sh`, файрвол хоста, `start.sh`. Скрипты лежат в `app/protocols/amnezia_scripts/awg/` с указанием коммита-источника. Сервер потом можно добавить в приложение AmneziaVPN по SSH — оно увидит клиентов бота | `55424/udp` |
| VLESS (Xray) | Официальный `ghcr.io/xtls/xray-core` (версия зафиксирована, обновление — кнопкой с changelog). VLESS + REALITY + Vision; запасной VLESS + XHTTP + REALITY. Цель REALITY проверяется на TLS 1.3 и h2. По умолчанию заблокированы BitTorrent и выход на RU-домены/IP | `443/tcp`, `8443/tcp` |
| Hysteria 2 | Официальный `tobyxdd/hysteria` (версия зафиксирована). Пароли проверяет бот (HTTP auth-хук), Salamander, BBR. Сертификат — Let's Encrypt по домену (нужен свободный `80/tcp` на время выпуска, продление — автоматически) или самоподписанный с `pinSHA256` в ссылке | `443/udp` |
| Сервер подписок | Внутри бота (aiohttp) | `2096/tcp` |

Свои контейнеры бот запускает с `--network host --restart unless-stopped --label vpnbot.proto=<id>`, их конфиги лежат в `data/xray/`, `data/hy2/`, сертификаты — в `data/certs/`.

Если включён `ufw` или `firewalld`, после установки бот предложит открыть порты отдельной кнопкой (молча ничего не открывает). Файрвол в панели хостинга (security groups) нужно открыть самостоятельно.

**XRay от Amnezia** (`amnezia-xray`) ботом не управляется — он показывается в «Протоколах». Кнопка «Заменить на оригинальный Xray» проходит все подтверждения удаления (с архивом `/opt/amnezia/xray/`), удаляет его и открывает мастер установки. Клиенты XRay из приложения после замены перестанут работать.

**Удаление** — кнопка «🗑 Удалить» в карточке протокола:

1. Экран «что будет потеряно»: контейнер, происхождение, сколько людей, устройств и клиентов из приложения затронуто.
2. Бот делает резервную копию, присылает её файлом и спрашивает «Точно удалить?». Для AWG и XRay от Amnezia можно отдельно отметить «удалить образ и данные».
3. Нужно прислать название протокола (`AWG`, `VLESS`, `HY2`) или 4-значный код с экрана, за 2 минуты. Любой другой ответ — отмена.

После удаления AWG-устройства удаляются из бота (трафик остаётся за людьми), у Xray/Hysteria2 креды пользователей сохраняются. Затронутые пользователи получают сообщение. Сеть `amnezia-dns-net` удаляется, только если к ней больше никто не подключён. Кнопки старых экранов после отмены или выполнения не срабатывают.

Перед каждой записью конфига сервера бот сохраняет копию в `data/backups/<протокол>/<время>/`.

## 9. Подписки и устройства (HWID)

У каждого пользователя одна ссылка подписки `https://SUB_HOST:SUB_PORT/sub/<токен>` со всеми установленными и работающими протоколами (VLESS, VLESS XHTTP, Hysteria2). Ссылки внутри — через домен `VPN_HOST`, не IP. Приложения обновляют подписку сами (раз в час).

- Если для `SUB_HOST` есть сертификат Let's Encrypt, подписки отдаются по HTTPS. Кнопка «Сертификат для подписок» в «Протоколах» выпускает его (нужен свободный `80/tcp`).
- Неизвестный или отозванный токен → `404`. Есть ограничение частоты запросов с одного IP.
- Отзыв доступа убирает пользователя из Xray и рвёт сессии Hysteria2; повторное одобрение возвращает.
- «Перевыпустить ссылку» — новые токен, UUID и пароль Hysteria2; старые подключения рвутся, список устройств подписки очищается.

**HWID и лимит.** Клиенты вроде Happ при обновлении подписки присылают идентификатор устройства (`x-hwid`, `x-device-os`, `x-ver-os`, `x-device-model`). Бот записывает устройство и показывает его в «Устройствах подписки». Новое устройство сверх лимита получает вместо серверов заглушку «Лимит устройств — удали лишнее в боте», а **сам пользователь** (не админ) получает сообщение с кнопкой «Мои устройства подписки» — не чаще раза в час на одно устройство. Клиенты без HWID учитываются как «неизвестное устройство» по User-Agent (или получают отказ при `HWID_REQUIRED=1`). Лимит — общий для AWG-устройств и устройств подписки.

> Честно: HWID ограничивает **получение подписки**, а не сами подключения. Ссылки, скопированные из подписки вручную, работают до перевыпуска ссылки. У всех устройств человека одни креды VLESS/Hysteria2 — протоколы это допускают; трафик подписки виден суммарно по человеку.

## 10. Использование

### Пользователь

- `/start` → **Отправить заявку** → ждёт одобрения.
- **🔗 Моя подписка** (если установлены VLESS или Hysteria2): ссылка, QR, кнопки «Открыть в …», устройства подписки с удалением, перевыпуск ссылки, инструкции.
- **🗂 Мои устройства / ➕ Добавить устройство** (если установлен AmneziaWG): ключ `vpn://`, QR-код, файл `.conf`, удаление.
- **ℹ️ Как подключиться** — инструкции по приложениям и раздельному туннелированию; **списки сервисов** — готовые файлы для импорта в клиенты.
- **📊 Статус** — устройства, подписка, онлайн и трафик по всем протоколам.
- **🆘 Не работает VPN** — проверка сервера из России и пошаговые решения; **💬 Написать админу**.

Если протокол остановлен, его карточки видны с пометкой «временно недоступен», выдача новых конфигов отключена. Если не установлено ничего — экран «VPN пока не настроен».

### Администратор

Кнопка **👑 Админка** или команда `/admin`:

- **🧩 Протоколы** — состояние, установка, удаление, обновление Xray, копии и восстановление.
- **👥 Пользователи** — карточка: устройства, подписка, трафик, отзыв/возврат доступа, личный лимит устройств, **✉️ Написать** и переписка.
- **⏳ Заявки**, **🚫 Отклонённые**, **📦 Из приложения** (клиенты AWG, выпущенные в AmneziaVPN), **📊 Дашборд** по всем протоколам.
- **📣 Рассылка** — несколько сообщений любых типов (текст с премиум-эмодзи, фото, альбомы, видео, документы, голосовые, кружки, стикеры, опросы), предпросмотр, группы получателей с числом людей («Сейчас в сети», «Активные за 24 ч / 7 дней», «Неактивные 30+ дней», по протоколу, все, заявки, выбранные вручную, только админы), без звука, закрепление, кнопка-ссылка, отложенная отправка (МСК). Отправка с ограничением скорости, продолжается после перезапуска бота, «Удалить у всех» (в пределах 48 часов). Шаблон **«Обновите подписку»** — после смены IP или настроек.
- **Мониторинг** — проверка доступности из России и инциденты.

Трафик считается накопительно: раз в минуту бот снимает счётчики (`awg`, API Xray, trafficStats Hysteria2) и копит прирост в базе — сумма не обнуляется при перезапуске контейнеров.

Страна сервера определяется по локальной базе [DB-IP Lite](https://db-ip.com) (CC BY 4.0), бот скачивает её сам.

## 11. Резервные копии и переезд

Формат — `.tar.gz` с `manifest.json` (тип, версия формата, происхождение, дата, порты, sha256 файлов):

- **awg** — `awg0.conf`/`wg0.conf`, ключи сервера, PSK, `clientsTable`, `start.sh`, параметры контейнера;
- **xray** — `config.json` и настройки (ключи REALITY, порты, SNI);
- **hy2** — конфиг, сертификат и ключ (или признак самоподписанного), пароль Salamander;
- **full** — все установленные протоколы + снимок `bot.db` + `.env` без `BOT_TOKEN` (токен — по отдельному выбору).

В копиях приватные ключи — **не пересылайте их никому**. Создание: «💾 Резервная копия» в карточке протокола, «Полная копия» в «Протоколах»; автоматически — перед удалением, заменой и восстановлением; по расписанию — `BACKUP_EVERY_DAYS`.

Восстановление: «♻️ Восстановить из копии» → прислать файл боту (до 20 МБ). Бот проверяет архив (манифест, хеши, версию, защита от выхода за пределы каталога), показывает, что будет восстановлено, и после подтверждения восстанавливает. AmneziaWG восстанавливается **с теми же ключами** — старые конфиги клиентов продолжают работать. Если протокол уже установлен, сначала удалите его (это сделает автокопию). После восстановления бот сверяет клиентов в конфигах с базой и предлагает добавить недостающих или удалить лишних.

**Переезд на новый сервер:** новый VPS → поставить бота (разделы 4–7) → «Восстановить из копии» (полная) → сменить A-запись домена → «📣 Обновите подписку». Конфиги AWG и подписки у пользователей остаются прежними.

## 12. Смена IP сервера и мониторинг блокировок

Если в `VPN_HOST` домен: смените IP у хостера, обновите A-запись — пользователи просто переподключаются.

Бот раз в несколько минут проверяет доступность сервера **из России** и из-за рубежа (check-host.net): TCP-порты Xray и сервера подписок, UDP — насколько позволяет сервис. Итог: всё хорошо / IP заблокирован / сервер недоступен / частично / не удалось проверить.

**Режим инцидента** открывается одинаково — по фоновой проверке или когда пользователь нажал «🆘 Не работает VPN»:

- администратору — уведомление с деталями по узлам и подсказкой «смени IP и обнови A-запись»;
- активным пользователям (в сети или действовали в боте за 10 минут) — сообщение, что администратор уже чинит; остальным — баннер при заходе в бота;
- пока инцидент открыт, бот следит за внешним IP сервера, A-записью `VPN_HOST` на резолверах 8.8.8.8, 1.1.1.1 и 77.88.8.8 (Яндекс) с учётом TTL, и проверяет новый IP из России;
- когда всё прошло — инцидент закрывается: админу — время простоя, всем, кто получил сообщение или баннер, — «VPN снова работает». Кнопка «✅ Починил» у админа только запускает внеочередную проверку.

## 13. Обновление

```bash
cd /opt/amnezia-bot
git pull
docker compose up -d --build
```

База и конфиги протоколов хранятся в `./data` и при обновлении не теряются. При обновлении со старой версии база мигрирует автоматически, существующие пользователи и устройства работают как раньше.

## 14. Решение проблем

**Бот пишет «Нет доступа к Docker»** — проверьте, что `/var/run/docker.sock` смонтирован (см. `docker-compose.yml`).

**Установка своих контейнеров падает с ошибкой пути** — бот не смог определить путь к `./data` на хосте; укажите `HOST_DATA_DIR=/opt/amnezia-bot/data` в `.env`.

**Порт занят** — мастер установки покажет, кто его занимает; выберите другой порт или освободите.

**Конфиг/подписка выдаётся, но не подключается**
- `dig +short vpn.example.com @8.8.8.8` должен вернуть IP сервера;
- порты протоколов открыты в файрволе хостинга и в `ufw`/`firewalld`;
- AWG: `docker exec amnezia-awg2 awg show` — появляется ли handshake;
- Xray: `docker logs vpnbot-xray`; Hysteria: `docker logs vpnbot-hysteria`.

**Сообщения без форматирования** — бот использует rich-сообщения; если они недоступны, присылает обычные. Обновите Telegram.

**Безопасность** — бот получает доступ к Docker через `/var/run/docker.sock`, то есть фактически root-доступ к серверу. Не передавайте никому `.env`, токен бота и резервные копии.

## 15. Проверка (чек-лист)

Юнит-тесты (без Docker): `pip install -r requirements.txt pytest && pytest -q`.

Ручная проверка:

- [ ] Пустой Ubuntu 24.04: бот стартует, пользователь видит «VPN не настроен».
- [ ] Установка AWG 2.0 из бота → устройство → подключение в AmneziaVPN; сервер добавляется в приложение AmneziaVPN по SSH и видит клиентов бота.
- [ ] Сервер с AWG и XRay, установленными приложением: бот показывает оба, AWG управляется, XRay помечен «не управляется»; «Заменить на оригинальный Xray» проходит все подтверждения и ставит XTLS Xray.
- [ ] Установка VLESS и Hysteria2 → «Моя подписка» → Happ на двух устройствах и Hiddify → трафик, статистика, оба устройства в списке.
- [ ] Лимит 1 → второе устройство получает «Лимит устройств», пользователю приходит сообщение, админу — нет.
- [ ] Перевыпуск ссылки → старые подключения рвутся.
- [ ] Удаление протокола: все три подтверждения, отмена на каждом шаге ничего не удаляет; после удаления пользователи получают сообщение.
- [ ] Копия AWG → удаление AWG → восстановление → старые конфиги клиентов подключаются без перевыдачи.
- [ ] Полная копия → чистый VPS → восстановление → смена A-записи → пользователи работают без новых конфигов.
- [ ] Битый или чужой архив → понятная ошибка, на сервере ничего не изменилось.
- [ ] Перезапуск контейнеров и бота → клиенты на месте, трафик не обнулился.
- [ ] Рассылка: текст с премиум-эмодзи + альбом из 3 фото + стикер → у пользователя в том же порядке, альбом одной группой; заблокировавший бота — в итогах; «Удалить у всех» работает; перезапуск посреди рассылки → продолжает с места остановки.
- [ ] Рассылка по группам «Сейчас в сети», «Активные за 24 ч», «Выбранные вручную» — правильные числа; «Написать» одному пользователю и его ответ доходит админу.
- [ ] Мониторинг: закрыть порт файрволом → инцидент, уведомление админу, сообщение активным, баннер у остальных; открыть порт → сообщение о восстановлении.
- [ ] Смена IP во время инцидента: «вижу новый IP» → обновление A-записи (в т.ч. на резолвере Яндекса) → проверка из РФ → инцидент закрыт; ошибка в A-записи → предупреждение админу.
- [ ] «Не работает VPN»: при бане — «передано администратору»; без бана — шаги решения; много нажатий подряд → одна проверка.
- [ ] Старые AWG-устройства работают как раньше.
